# Full-Paper Workflow

## Contents

1. Intake
2. Argument map
3. Section architecture
4. Draft order
5. Coherence pass
6. Compression pass

## 1. Intake

Collect the manuscript, abstract, exhibits, appendix, verified references, and any editor/referee instructions. Establish which artifacts are authoritative when numbers disagree.

Create three compact working artifacts:

- a fact ledger;
- a claim–evidence matrix;
- a reverse outline of the current draft.

Use the templates in `assets/`. Do not begin sentence polishing until the contribution and evidence chain can be stated without contradictions.

## 2. Build the argument map

Complete this chain:

```text
economic tension
→ precise question
→ why existing evidence cannot answer it
→ setting/model and source of leverage
→ main finding with magnitude
→ mechanism or interpretation
→ contribution and boundary
```

For each arrow, ask whether the transition is logical or merely rhetorical. A missing arrow is usually a substantive gap, not a prose problem.

## 3. Choose functional modules

Include a section only when it performs a necessary job.

- Put a compact institutional background before design when readers need rules, timing, or market structure to understand variation.
- Put a standalone literature section only when multiple literatures require careful synthesis beyond the introduction.
- State formal hypotheses only when theory generates discriminating predictions and later tests return to them.
- Separate data from design when measurement/sample construction is independently complex.
- Separate mechanisms from robustness when the mechanism evidence answers a different question from design validity.
- Put long derivations, variable dictionaries, auxiliary designs, and exhaustive specifications in the appendix.

## 4. Draft in evidence-first order

A reliable drafting order is:

1. Main tables/figures and exact result statements.
2. Data, design/model, and result sections.
3. Robustness, mechanism, and appendix map.
4. Introduction and contribution.
5. Abstract and title.
6. Conclusion.

This order prevents the front matter from promising evidence the paper does not deliver.

## 5. Run the coherence pass

Check these repeated objects across every section:

| Object | Consistency question |
|---|---|
| Question | Is the same estimand/economic question being answered? |
| Sample | Are dates, units, exclusions, and N aligned? |
| Main result | Are sign, units, magnitude, and benchmark identical? |
| Design | Are the same assumptions and limits acknowledged? |
| Contribution | Does every claimed contribution appear in the evidence? |
| Mechanism | Is the wording equally cautious across abstract, introduction, and results? |
| Terminology | Does each construct keep one name and definition? |

Inspect tables and footnotes; inconsistencies often originate there.

## 6. Run the compression pass

Remove or merge prose that:

- repeats a result without adding interpretation;
- surveys distant literature rather than sharpening the gap;
- gives implementation detail before the reader knows why it matters;
- lists robustness tests without naming threats;
- restates every table coefficient;
- uses throat-clearing transitions;
- claims importance instead of demonstrating economic stakes.

Preserve limitations, assumptions, and economically material nulls. Compression must not make the paper sound more certain than the evidence.
