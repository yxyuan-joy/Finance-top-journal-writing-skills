# Referee Response and Revision Strategy

Read this reference when converting an editor letter, referee report, seminar memo, or internal review into a revision plan, point-by-point response, and synchronized manuscript changes. Do not use it merely to polish an untouched draft.

## Build one revision control table

Before drafting responses, decompose every comment into an auditable row:

| Field | Record |
|---|---|
| ID | Editor/referee and comment number |
| Request | The concrete question, concern, or requested analysis |
| Underlying issue | Claim, contribution, design, measurement, interpretation, scope, exposition, or compliance |
| Priority | Decision-critical, major, useful, or optional |
| Action | Analysis, rewrite, reorganization, clarification, bounded non-adoption, or factual correction |
| Evidence | Existing or new table, figure, derivation, citation, diagnostic, or author decision |
| Manuscript locations | Every section and exhibit that must change |
| Response location | Response-letter subsection and final page/section anchors |
| Status | Planned, executed, validated, or unresolved |

Preserve the original wording of each comment in the working table. Split compound comments into subparts so that a long answer cannot conceal an unanswered request.

## Triage by consequence

Read the editor's letter first to identify decision priorities and any explicit limits, but do not assume silence means a referee concern is optional. Treat a comment as decision-critical when it challenges the research question, novelty relative to the nearest literature, validity of the main design/model, measurement of a central construct, interpretation of the main result, or feasibility of the revision.

Resolve dependencies before running analyses. A changed estimand can invalidate planned robustness tests; a revised sample can alter every exhibit; a narrower claim can make an expensive requested extension unnecessary. When reports conflict, identify the underlying objective and propose one coherent treatment. Explain the tradeoff rather than telling one reviewer that another disagreed.

## Match the response to the action

Use this sequence for each point:

1. Acknowledge the precise concern without generic gratitude padding.
2. State the action and the substantive answer in the first paragraph.
3. Describe new evidence or reasoning, including result, units, uncertainty, and boundary.
4. Explain how the interpretation changed.
5. Identify all manuscript locations with stable section, table, figure, or page anchors.

If the analysis is infeasible or the requested change would be misleading, do not fake compliance. State the shared objective, document the constraint, provide the closest valid diagnostic or rewrite, and narrow the claim. Use bounded non-adoption only when the evidentiary reason is clear; inconvenience alone is not a justification.

## Synchronize response and manuscript

Treat the response letter as an index to actual changes, never as a substitute for them. After resolving a comment, update all affected components:

- title and abstract if the question, sample, design, or main finding changed;
- introduction and contribution statements if scope or closest-literature positioning changed;
- data/design sections, equations, variable definitions, and sample flow if implementation changed;
- tables, figures, notes, appendix, and cross-references if evidence changed;
- results, mechanisms, discussion, and conclusion if claim strength or interpretation changed.

Keep each coefficient, uncertainty measure, sample, benchmark, and specification together. Never describe an old table in the manuscript while citing a revised result in the response. Run the cross-section consistency inventory after material changes.

## Write for verification

Make the answer self-contained enough for the editor or referee to verify the disposition without reconstructing the paper. Distinguish `we now show`, `we now clarify`, and `we now limit`; they are not interchangeable. Quote only short changed passages when they help verification, and use page/section anchors that correspond to the submitted clean manuscript.

Do not claim that a new result “fully addresses” a concern unless it tests the relevant threat. Report inconvenient, null, or mixed evidence and adjust the claim. Do not add unsupported citations, retrospective hypotheses, or analyses described only in the letter.

## Final revision audit

Before delivery, verify that every comment row has a disposition, every asserted change exists in the manuscript, all new analyses are interpreted at the correct claim level, and no response introduces a stronger conclusion than the revised paper. Re-read the editor letter last: confirm that the revised paper presents one coherent contribution rather than an accumulation of disconnected referee requests.
